CONTEXTO: Projeto Lovat Bot (Discord bot em Python, discord.py 2.x), com
dashboard Flask integrado (pasta webapp/) rodando no mesmo processo do bot
em thread separada. Sistema de configuração por servidor já existe em
config/guild_config.py (funções get_guild_config, save_guild_config,
update_guild_config, lê/escreve data/guilds/{guild_id}.json). O painel
admin exclusivo do dono já existe em webapp/routes_owner.py e
templates/owner_panel.html / owner_users.html.

Implemente as duas tarefas abaixo, uma de cada vez, testando a sintaxe
com "python3 -m py_compile" em cada arquivo alterado antes de seguir
para a próxima. Ao final de cada tarefa, faça um commit git separado
com mensagem descritiva.

=========================================
TAREFA 1 — Seção "Configurações" no painel admin do site
=========================================

Objetivo: adicionar uma nova página /painel-admin/configuracoes no
dashboard, acessível só pelo dono do bot (mesma checagem de
OWNER_DISCORD_ID já usada em webapp/routes_owner.py), com duas partes:

A) Textos/mensagens padrão do bot
   - Criar um arquivo config/bot_settings.py (se não existir) com um
     dicionário de mensagens editáveis, por exemplo: mensagem de boas-
     vindas padrão, mensagem de despedida padrão, mensagem de erro
     genérica, rodapé padrão dos embeds. Persistir em
     data/bot_settings.json (funções get_bot_settings() e
     update_bot_setting(key, value), seguindo o mesmo padrão de leitura/
     escrita de config/guild_config.py).
   - Na página /painel-admin/configuracoes, mostrar um formulário com
     um campo de texto para cada mensagem configurável, com botão
     "Salvar" que faz POST para uma rota nova
     (owner.salvar_configuracoes) que chama update_bot_setting para
     cada campo enviado.
   - Onde essas mensagens já são usadas com texto fixo no código atual
     (ex: mensagens de boas-vindas/despedida, se existirem em
     systems/ ou commands/), trocar para ler de get_bot_settings() em
     vez de string fixa, mantendo um valor padrão caso a chave não
     exista ainda no JSON.

B) Ligar/desligar sistemas inteiros
   - No mesmo arquivo config/bot_settings.py, adicionar uma seção
     "sistemas_ativos" com chaves para cada sistema desligável:
     "economia", "musica", "tickets", "moderacao", "social",
     "diversao", "utilidades" — todas True por padrão.
   - Na página /painel-admin/configuracoes, mostrar um toggle/checkbox
     para cada sistema, com o mesmo formulário salvando via
     update_bot_setting.
   - Nos comandos correspondentes a cada sistema (ex: todos os
     arquivos dentro de commands/ que pertencem a economia: saldo.py,
     daily.py, apostar.py, raspadinha.py, admin_economia.py — e assim
     por diante para os outros sistemas), adicionar uma checagem no
     início de cada comando: se o sistema estiver desativado nas
     configurações, responder com uma mensagem ephemeral tipo
     "⚠️ Esse sistema está temporariamente desativado pelo
     administrador do bot." e não executar o resto do comando.
   - Não precisa desregistrar o slash command do Discord (fica mais
     simples só bloquear a execução) — só a checagem de
     "sistema ativo?" no início de cada função de comando já resolve.

Adicionar a rota nova em webapp/routes_owner.py, o template
templates/owner_config.html (seguindo o mesmo estilo visual das outras
páginas do painel admin — reutilizar classes CSS já existentes como
.field-control, .btn, .owner-guild-card), e o link "Configurações" na
navbar (templates/base.html) dentro do bloco "{% if is_owner %}", do
mesmo jeito que os links "Painel Admin" e "Usuários" já aparecem lá.

TAREFA 2 — Embed do /perfil mais completa
=========================================

Objetivo: melhorar visualmente o embed retornado pelo comando
/perfil ver (arquivo commands/perfil.py), que hoje está muito básico.

Adicionar ao embed:
- Uma barra de progresso em texto (usando caracteres de bloco, tipo
  "▰▰▰▰▰▱▱▱▱▱" ou similar) mostrando o progresso de XP até o próximo
  nível, calculado a partir das funções já existentes em
  systems/social.py (calc_level, get_user_social). Adicionar uma nova
  função em systems/social.py chamada xp_progress(xp: int) que retorna
  uma tupla (xp_atual_no_nivel, xp_necessario_para_proximo_nivel,
  percentual) baseada na mesma fórmula usada em calc_level.
- Mostrar o nível atual em destaque no título do embed (ex:
  "Perfil de {nome} — Nível {nivel}").
- Mostrar saldo de moedas (via systems.economy.get_saldo) e reputação
  (campo "reputacao" já existente em get_user_social) como campos
  separados do embed, com emojis (💰 para saldo, ⭐ para reputação).
- Manter a exibição da bio já existente.
- Usar embed.set_thumbnail com o avatar do usuário (se já não estiver
  fazendo isso) e uma cor de destaque diferente dependendo da faixa de
  nível (ex: nível 1-4 cor padrão EMBED_COLOR, nível 5-9 dourado
  0xF1C40F, nível 10+ roxo 0x7B2FF7) — não precisa ser exato, escolha
  faixas razoáveis.

Não altere o comando /perfil editar (edição de bio), só o /perfil ver.
